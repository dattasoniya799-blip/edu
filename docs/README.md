# qiming/docs · 仓库技术文档

这个目录放**随代码一起演进**的技术文档:架构地图、模块说明、排障与运维笔记。
和代码同仓同分支,改代码的那个 PR 就该顺手改文档。

## 这里放什么 / 不放什么

| 放 | 不放 |
|---|---|
| 架构总览、模块职责、数据流 | 主系统产品需求与任务卡(在 `../../启明智学-开工包/`) |
| 动画课堂学生端 demo 需求(`02-…`) | 教师端制作、分发、主系统挂接(尚未立项,不写进开工包) |
| 「改某类东西要动哪些文件」的操作指南 | 项目当前进度与路线图(在 `../../项目状态与路线图.md`) |
| 数据库/契约/部署的结构性说明 | 协作纪律与契约变更记录(在 `../../启明智学-开工包/01-项目宪法.md`) |
| 踩过的坑、非显然的约定 | 外部调研(在 `../../_research/`) |

`qiming/README.md` 是**交付记录/变更日志**(按任务波次追加),不是架构说明;
需要「现在长什么样」看本目录,需要「为什么变成这样」看那份 README 和宪法。

## 命名约定

`NN-中文标题.md`,两位数字前缀表示阅读顺序,新增文档取下一个可用编号。
文档内首段写清「这篇解决什么问题、写给谁看」,末尾注明生成日期与「基于当时代码状态」。

现有文档:

| 文件 | 内容 |
|---|---|
| `01-架构总览.md` | 改代码前先看的地图:目录职责、后端/前端架构、典型数据流、常见改动指南 |
| `需求文档/02-动画课堂-学生端demo需求.md` | 动画课堂 demo 的学生端需求(一套上课页、三堂课) |
| `需求文档/2026-08-31-动画课堂-学生端demo-计划.md` | 上条需求的实现计划 |
| `03-多机构登录改造方案.md` | **待命方案**:跨机构登录串号的完整改造设计(orgCode+复合唯一),第二家机构接入前执行 |

## 维护要求

**改动大的功能后必须同步更新架构文档。** 具体地,出现下面任一情况时,`01-架构总览.md` 必须在同一波工作里改掉:

- 新增/删除 app 或 package,改端口、改启动方式
- 后端新增/合并模块(`apps/server/src/<模块>/`),或调整全局守卫、拦截器、中间件
- `prisma/schema.prisma` 增删表,或新增迁移
- `packages/contracts` 的端点集合、DTO 结构、WS 协议发生变化
- 引入新的基础设施(队列、缓存键族、外部服务、存储驱动)
- 部署形态变化(nginx 路由、compose 服务、镜像构建方式)

只改页面文案、修 bug、加测试不需要动本文档。
更新时同步刷新文末的日期,不要留着旧日期加新内容。
