# qiming/docs · 仓库技术文档

这个目录放**随代码一起演进**的文档:协作纪律、架构地图、风格基线、待命方案、需求与留档。
和代码同仓同分支,改代码的那个提交就该顺手改文档。AI 会话从仓库根 `AGENTS.md` 进来后,先读 `00`、`01`。

## 这里放什么 / 不放什么

| 放 | 不放 |
|---|---|
| 协作纪律与红线(`00`)、架构总览与改动指南(`01`)、前端风格基线(`02`) | 契约变更的逐条记录(在 `../packages/contracts/CHANGELOG.md`,与契约同处) |
| 待命的技术方案(`03` 多机构登录) | 项目当前进度与路线图(在 `../../项目状态与路线图.md`,工作区级) |
| 验收操作手册(`04`) | 按波次追加的交付日志(在 `../CHANGELOG.md`) |
| `需求文档/`:仓库内功能的需求、实现计划、下线留档 | 外部调研(在 `../../_research/`)、历史任务卡与设计文档(已归档到 `../../_archive/启明智学-开工包-2026-06/`) |
| 踩过的坑、非显然的约定 | 仓库外的脚本 / 模型实验记录(在 `../../_lab/`) |

## 命名约定

- 顶层:`NN-中文标题.md`,两位数字前缀表示阅读顺序,新增文档取下一个可用编号(当前 `00`–`04` 已用)。
- `需求文档/`:`YYYY-MM-DD-主题.md`,日期为立项 / 决策日;同一主题的需求、计划、留档同前缀。
- 文档内首段写清「这篇解决什么问题、写给谁看」,末尾注明生成 / 更新日期与「基于当时代码状态」。

## 维护要求

**改动大的功能后必须同步更新架构文档。** 具体地,出现下面任一情况时,`01-架构总览.md` 必须在同一波工作里改掉:

- 新增 / 删除 app、package 或 lab 项目,改端口、改启动方式
- 后端新增 / 合并模块(`apps/server/src/<模块>/`),或调整全局守卫、拦截器、中间件
- `prisma/schema.prisma` 增删表,或新增迁移
- `packages/contracts` 的端点集合、DTO 结构、WS 协议发生变化(同时在 `packages/contracts/CHANGELOG.md` 追加记录)
- 引入新的基础设施(队列、缓存键族、外部服务、存储驱动)
- 部署形态变化(nginx 路由、compose 服务、镜像构建方式)、根编排脚本或 CI job 变化

改 `00` 第一节(顶层目录、红线)属纪律变更,需用户批准并记入其第五节。
只改页面文案、修 bug、加测试不需要动本目录。更新时同步刷新文末的日期,不要留着旧日期加新内容。
