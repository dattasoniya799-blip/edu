## 一、为什么要这样查

现有自动化有一层盲区:后端 e2e 只打 API、vitest 只测纯函数、三端 mock 冒烟打的是 msw 假数据——三者都不碰
「真实后端 + 真实数据 + 真浏览器」。用户报的 5 个问题全在这一层。所以本轮的主体是**浏览器级真实模式走查**,
辅以静态审计(契约–实现–前端–mock 四方对照、分类维度矩阵)与 API/DB 交叉验证。

原则:按「用户任务」走而非按页面点;每步记预期 / 实际 / 证据;先定位根因层(契约 / 后端 / 前端 / seed / 环境 / 产品口径)再归并;
不边查边改(P0 阻断除外);契约缺口走申请。
