# 02 · 动画课堂 · 学生端 Demo 需求

> **这篇写给谁**:做动画课堂 demo 的人(包括 AI 会话)。目标是把「学生打开就能上一堂动画课」做成可演示的成品。
> 教师制作、班级分发、主系统挂接不在本文范围。
>
> **一句话**:教师以后制作、学生现在先看。Demo 只交学生端:一套上课页,三堂课,能听、能看、指定拍能动手。
>
> 已确认决策(2026-08-31):覆盖知识点 + 讲题;形态统一为讲解剧本;学生端先行;本轮只打磨坐标系上的三堂课。

---

## 一、背景与要解决的问题

OpenMAIC、DeepTutor 都是「本机提需求、本机出课」:生产和消费是同一个人。我们要的是老师做、学生看——一次制作、多人讲解。那是下一阶段。

当前实验区已经有两套学生能碰到的东西,但还不是一堂课:

| 现有 | 位置 | 学生实际拿到的 |
|---|---|---|
| 知识点动画 | `apps/lab/public/animations/` 共 5 个单文件 HTML | 实验页:画布 + 滑杆 + 底部反馈。几乎没有老师在讲 |
| 动态讲义 | `apps/lab/src/experiments/dynamic-lecture/` 1 道弹簧题 | 双栏播放器能步进、能语音,但界面挤、口吻不像上课、滑杆在观看拍也占着 |

四类问题(本 demo 要改掉):

1. **视图**:两套界面各讲各的,没有「进了一堂课」的统一舞台。
2. **教学语言**:不是老师说出口的话;学段用语不稳。
3. **教学方式**:知识点没有引入→展开→结论→收尾;画面堆、拍太快。
4. **动画成品**:现有 HTML / 旧播放器只当素材,不再当学生入口。

借鉴只取学生能感知的部分:

| 来源 | 采用 | 不采用(本轮) |
|---|---|---|
| OpenMAIC | 讲稿是口语、不播报动作;说话和画面同时发生;每拍只钉一个想法 | 多智能体、白板账本、导出 zip、教师工作台 |
| DeepTutor | 概念拍:比喻 → 定义 → 例子 → 误区;至少 5 个教学拍;画面质检(重叠、过密、没讲完就结束) | 本机自助生成、Manim 出视频、费曼检查入口 |
| 本仓库已有 | 讲解剧本契约、坐标系 Canvas 缓动引擎、纸感外壳、弹簧题样本、5 个动画的数学关系 | 两套入口、禁用滑杆占位、HTML 车间当学生课 |

## 二、目标与非目标

**目标**:在 `apps/lab`(永不部署)交出可演示的学生课堂。打开一堂课就是整页上课,走完能听懂、画面跟得上、动手拍有用。

**非目标**(明确不做,不写半截):

- 教师制作台、审查流、发布
- 班级分发、课堂 WebSocket 同步步进、作业/错题本挂载
- 改 `packages/contracts`、主系统三端、数据库
- 真人声 TTS(继续浏览器语音占位;无中文语音则字幕模式)
- 几何场景族(勾股正方形、椭圆轨迹等)
- 把现有 5 个 HTML 全部改成课
- 视频导出、学生自由出题、手机竖屏作为设计目标

设备仍按既定口径:电脑浏览器 + 机构平板/一体机。主题走纸感暖米白,不用调研对象的暗色。

## 三、学生视图

进课即整页舞台,实验区列表退场。一堂课只有这一层,不允许「列表 + 上课 + 剧本」叠在同一屏。

```
┌─────────────────────────────────────────────────────────────┐
│  ← 返回课表    课名 · 学段                    课堂(无剧本页签) │
├────────────────────────────────────┬────────────────────────┤
│                                    │  步骤条(短名,可点跳步)   │
│  主图(约 60%)                       │  本拍讲解(屏显)         │
│  高度锁死,不参与滚动                 │  口语字幕(语音关/无中文  │
│  画面随拍出现、替换、淡出             │      语音时显示)        │
│                                    │  可选小问 / 三级支架     │
│                                    │  (本栏独立滚动)          │
├────────────────────────────────────┤                        │
│  动手拍才出现的一根滑杆              │                        │
│  观看拍这里是空的,不放禁用杆         │                        │
├────────────────────────────────────┴────────────────────────┤
│  上一步  下一步  重听本拍  连播  语音                         │
└─────────────────────────────────────────────────────────────┘
```

硬规则:

- 主图完整可见,不因步骤长短或右栏滚动而缩放跳变。
- 控制只留:上一步、下一步、重听本拍、连播、语音。倍速可放在语音旁,不作为验收项。不要「从头演一遍」(点步骤条第一拍即回到开头)。「剧本」页签对学生隐藏;需要核对讲稿时在上课 URL 加 `?dev=1`。
- 知识点课没有「原题」折叠栏。讲题课原题默认收起,需要时点开。
- 滑杆只在本拍声明了 `interaction` 时出现,一次只开放一个量。观看拍不渲染禁用滑杆。
- 触控目标 ≥ 44px;无仅 hover 才出现的提示。
- 进课即开讲,不另设「开始」封面(浏览器语音手势用进课那一次点击解锁)。

课表(实验区二级页):三张课卡片,点一张进入上课页。不再并列「知识点动画车间」和「动态讲义」两个学生入口。原 HTML 车间若仍保留,标为「素材/校验,非上课」。

## 四、教学语言

两条文本,职责不许混:

| 字段 | 给谁 | 规则 |
|---|---|---|
| `display` | 眼睛 | 可含 `$...$` 公式;短、可扫读;本拍一个想法 |
| `narration` | 耳朵 / TTS | 说出口的完整句子。无 markdown、无项目符号、无「我来画」「接下来添加」。画面自己出现,嘴上只讲数学 |

学段用语(本 demo 三课都按八年级到高一口径写):

- 八年级一次函数:说「k 的意义 / 涨得快慢 / x=0 时的 y」,不说「斜率」「截距」。
- 高一导数:可以说切线、割线、Δx、导数;不讲求导法则、不讲单调性。
- 数字读法写进讲稿:「零点五」而不是「0.5」塞进 TTS;屏上仍写 0.5。

概念拍结构(DeepTutor 讲解顺序,压进该拍的 `display` + `narration`):一句生活里能接上的比方 → 准确定义 → 一个具体例子 → 点出本课那一条误区。不是每拍都走完四段,引入拍和结论拍各承担其中一段。

反馈:说当前数值说明的规律或不变量。禁止只报对错。动手拍的实时反馈随滑杆更新,且点出「哪一个量没变」。

## 五、教学方式

每课至少 **5 拍**,默认顺序:

1. **引入** — 最小画面(坐标系或一条曲线)+ 本课要亲手得到的那一个结论的预告,不给公式。
2. **展开 1** — 第一个关键关系(只动一个因素)。
3. **展开 2** — 第二个关键关系,或把展开 1 反过来看。
4. **关键结论** — 公式或定理式只允许在这一拍及之后出现;指定一拍放手让学生拖一个量。
5. **收尾** — 再看一遍全过程(可用参数扫描),点出边界或误区,稳定停留,不立刻结束。

拍的纪律(OpenMAIC 白板纪律改写到我们的场景):

- 每拍只钉一个想法。新元素出现前,与本拍无关的标注淡出或替换,不在同一帧堆满。
- 说话和画面同时发生:进入该拍即执行 `sceneActions` 并朗读 `narration`。
- 连播时本拍至少停留到讲稿读完;无中文语音时按字数留阅读时间,禁止几秒刷完。
- 动手拍:连播停住提示「轮到你」;学生拖了就接管;若干秒不操作则继续,预测小问永不挡路。
- 关键结论拍必须有一次学生操作,或有一次「一键调到目标值」。不允许整堂课纯观看。

画面质检(DeepTutor 视觉审查,人审时逐课过):标签/公式/线是否重叠;关键对象是否出画或过小;是否一拍塞了太多内容;是否没讲完就结束。不过则改剧本和场景,不靠播放器补救。

## 六、Demo 三课

全部走坐标系场景族(`scene.family = 'coordinate'`)。现有元素白名单优先:函数曲线、点、线段、文字、台阶。导数课若「割线躺向切线」看不清,允许新增一种「余晖轨迹」元素;能用点 + 线段看清则不加。

| id | 类型 | 学段 | 认知动作 | 学生 60 秒内得到的结论 | 指定误区 | 动手拍开放的量 |
|---|---|---|---|---|---|---|
| `kp-linear-kb` | 知识点 | 八年级 | 变换 | k 管倾斜,b 管上下,改一个另一个不动 | 把 b 当成与 x 轴的交点;以为 k 变了交点也跑 | 先 k 后 b,一次一根 |
| `kp-derivative-secant` | 知识点 | 高一 | 逼近 | Δx 越小,割线越贴切线,极限斜率就是导数 | 以为导数是套公式算出来的;以为 Δx 必须等于 0 | Δx(可附「让 Δx 趋近 0」) |
| `math-linear-spring-1` | 讲题 | 八年级下 | 程序/建模 | 原长是 b、每千克伸长是 k;已知 y 求 x 要解方程 | 两个系数对调;已知 y 却把长度当 x 代入 | 所挂质量 m |

内容来源:一次函数 / 导数课从现有 HTML 抽数学关系与巡航意图,按第五、六节重写成剧本,不把 HTML 嵌进上课页。弹簧课改写现有 `spring-linear.ts` 的讲稿、拍序和界面占用,数学关系保留。

每课必须带 `reference` 自查算例(机器代入核对)。不过质检门的剧本不进入播放器。

## 七、剧本与播放器

**剧本是中枢。** 学生端、以后的教师端、TTS、分发都读同一份格式。本轮只手写三份剧本,不上 AI 拆解管线。

相对现有 `script-schema.ts` 的必要增量:

1. 增加 `kind`: `'concept' | 'problem'`。`concept` 不要求原题 `problem`;用 `goal` 一句话定位(即「学生 60 秒内得到的结论」)。`problem` 课保留原题字段。
2. `steps` 下限改为 5。
3. `label` 必填,4–6 字,作步骤条短名。
4. 观看拍不得带 `interaction`;全课至少一拍带 `interaction`。
5. `schemaVersion` 仍为 `'0.1'`,用 `kind` 作扩展判别,不另开版本号。

播放器只读校验通过的剧本:

- 按步重放 `sceneActions`,任意步幂等可达(已有行为,保留)。
- 坐标系渲染继续用现有双轨缓动引擎(target / current),画面变化不闪现。
- TTS:一步一段,浏览器占位;讲稿变更才重录(本轮手写,无预生成文件也可现场合成)。
- 校验失败:上课页只报错,不播放。

实验区入口改为一个实验:「动画课堂」,下列三张课卡。`KpAnimations` 车间不再作为上课路径。

## 八、验收

由人按学生走完三课,下列全部成立才算 demo 过:

1. 从实验区点进任一课,整页上课,没有实验区外壳、没有剧本页签、没有禁用滑杆。
2. 能听完(或字幕读完)至少 5 拍;连播不会在讲完前跳步。
3. 关键结论拍能动手,拖一个量时画面与反馈同时变,且反馈说出不变量。
4. 公式不出现在引入拍;收尾拍有停留,不是讲完立刻黑屏或返回。
5. 八年级两课听不到「斜率」「截距」;三课讲稿都没有「我来画」「接下来添加」。
6. `npm run validate:anim` 与现有 HTML 校验互不干扰;三份剧本能被 schema + 自查算例拦住坏稿。
7. `apps/lab` 的 `npm run build` 通过。不要求主系统 e2e、不要求进 CI。

不验收:教师能否生成、学生账号能否收到、课堂是否全班同步。
