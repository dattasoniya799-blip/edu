## 一、八条硬纪律

> 代码注释与测试名里的「宪法 §N」即指本节第 N 条(编号沿用原宪法,未重排)。

1. **Monorepo 结构固定,不得增删顶层目录**:
   `apps/server`(NestJS)· `apps/admin` · `apps/teacher` · `apps/student`(React + Vite)——`apps/` 只放可部署的应用;
   `labs/playground`(前端实验区,永不部署、不进主线门禁;2026-09-02 自 `apps/lab` 迁入,`labs/*` 每个目录一个实验项目);
   `packages/contracts`(契约,**只读!**)· `packages/ui`(共享组件)· `data/`(知识图谱等数据)·
   `deploy/`(生产编排)· `docs/`(本目录:协作纪律 / 架构总览 / 风格基线 / 方案与需求)。
2. **只允许创建/修改本次任务「负责目录」内的文件**。需要改别处 → 停下,输出「契约变更申请」(见第三节)。
3. **类型与枚举一律 `import` 自 `@qiming/contracts`,禁止重复定义**;接口调用一律走 contracts 的 `createClient()`,
   **禁止手写 fetch**;前端**禁止裸写十六进制色值**,颜色只来自 design-tokens。
4. **后端:所有数据库访问通过注入的 `PrismaService`**(已内置 org_id 租户注入),禁止原生 SQL、禁止绕过注入、
   禁止在业务模块 import 任何 LLM 供应商 SDK(只许调 AiGateway / LlmGatewayService 接口)。
5. **前端:后端未就绪时用 msw 按 `packages/contracts/openapi.yaml` 起 mock**;mock 数据集中放 `src/mocks/`,禁止散落在组件里。
6. **每个任务交付必须含:代码 + 测试 + 简短 README**(怎么跑、覆盖了哪些验收项)。验收标准在任务卡里,不达标不算完成;
   **不做任务卡之外的任何「优化」**。
7. **安全红线:学生为未成年人**——手机号等敏感字段不得出现在日志;任何接口不得返回他人 org 的数据
   (**测试必须包含跨租户 404 用例**,凡涉及查询的任务都适用)。
8. **发现纪律或契约有错:停止编码,输出「契约变更申请」**(改什么 / 为什么 / 影响哪些任务),等待人工决策。
   **禁止自行修改 `packages/contracts` 与 `prisma/schema.prisma`。**

## 二、流程纪律(实践中固化下来的)

- **任务分支施工**:`task/<名字>`;主工作树平时停在 `main`。同一时刻多个会话必须在不同分支、不同负责目录。
- **全绿才合 main**:仓库根 `npm run check:all` + `npm run test:mock` 绿;涉及后端的波次合并前跑**全量 e2e**
  (`npm run e2e`,鲜库重建 + 三段 seed,`E2E_LLM_ISOLATION=1`;`d2-init-prod` 套件须无沙箱执行)。
  实验区 `npm run check:labs` 不在门禁内,红了修掉即可,不拦合并。
- **merge commit 题头** `merge: task/<名字>——<一句话交付 + 验证结果 + 日期,经用户批准>`;合并后删本地任务分支。
- **push 必须用户确认**;git 身份沿用 `apple1 <apple1@MacBook-Air.local>`,不改 config。
- **改契约 = 申请 → 批准 → 改 → `npm -w @qiming/contracts run gen:sdk && npm -w @qiming/contracts run lint:openapi`
  → 同一提交在 `packages/contracts/CHANGELOG.md` 末尾追加记录。**
- **改动大的功能后必须同步更新 `docs/01-架构总览.md`**(触发条件见 `docs/README.md` 的「维护要求」);
  改本文第一节(顶层目录、红线)属纪律变更,需用户批准并记入第五节。
- 新功能一律先进 `labs/`(本地实验)或功能开关 `beta`(白名单),不直接上 `ga`(见 `docs/01` 5.8)。

## 三、「契约变更申请」怎么写

停下当前编码,输出三段:**改什么**(文件 / 字段 / 端点 / 迁移与否)、**为什么**(用户原话或缺口证据)、
**影响哪些任务 / 端**(哪些 mock、fixture、页面会跟着红)。等用户批准后再动手;批准文本即记录的口径依据。
