# 知识点动画 skill（初高中 · 单文件交互 HTML）

本文件是 qiming 实验区生成「初高中知识点动画」的作业指令。
一次生成走三段:**EVAL(值不值得做)→ PRD(想清楚做什么)→ CODE(按规范写出来)**。
EVAL 不过线就停,不要硬写;PRD 没写完不许进 CODE。

产物只有一种形态:**零依赖单文件交互 HTML**。原生 HTML + CSS + JavaScript,
画图用 Canvas 2D 或内联 SVG,单文件目标 30KB 级、硬上限 120KB,不引任何外部资源。
动画是内容资产,不是前端代码:本阶段先落在
`apps/lab/public/animations/{初中|高中}/<中文文件名>.html`,人审通过后再谈上资源库。

调用格式(给生成方的输入):

```
知识点: 一次函数 y=kx+b 的图象与性质
学段: 初中
知识图谱节点: MATH-JH-8B-19-CP13   # 查不到就写「无」
```

---

## 一、EVAL — 先判断值不值得做动画

多数知识点不需要动画。一张静态图、一段文字讲得清楚的东西,做成动画只是浪费人审工时,
还会让学生把注意力花在玩控件上。所以每个候选先打两个分,再看拦截线。

### 打分维度一:动态收益(1–5)

问的是「静态表达做不到的事情有多少」。

| 分 | 判据 |
|---|---|
| 5 | 概念的核心就是一个过程或极限,截图之后概念本身就消失了(逼近、收敛、连续变形) |
| 4 | 概念里有明确的「变量—不变量」结构,静态要画好几张图并排才说得清 |
| 3 | 动起来更好懂,但一张标注到位的静态图也能完成教学 |
| 2 | 只是把已有插图做得更好看,理解难度没降 |
| 1 | 纯记忆或纯计算内容,视觉表达没有增益 |

### 打分维度二:交互必要性(1–5)

问的是「学生非得自己动手吗」。

| 分 | 判据 |
|---|---|
| 5 | 不亲手改参数就无法发现规律,规律藏在「我改了它,它跟着变」里 |
| 4 | 自己操作明显优于看录播,但看演示也能得到大半 |
| 3 | 交互有加成,一段自动播放的动画基本够用 |
| 2 | 交互只是换个方式点下一页 |
| 1 | 纯阅读内容,给控件反而干扰 |

### 拦截线(硬规则)

- 两项都 ≥ 4 → 直接做,优先级高。
- 两项之和 ≥ 7 且没有任何一项 = 1 → 做。
- 两项之和 ≤ 6 → **拦下**,在 EVAL 里写明「建议改为静态讲义/例题」,不产出 HTML。
- 任一项 = 1 → **拦下**,不管另一项多高(动态收益 1 说明没得可视化;交互必要性 1 说明做成动画只是播片)。

### EVAL 输出格式

```
知识点:一次函数 y=kx+b 的图象与性质
动态收益:4 —— k、b 各自控制一种性质,静态要画一族直线才能说清
交互必要性:5 —— 「k 变大直线变陡但过 y 轴的点不动」必须自己拖才有体感
结论:通过(4+5=9)。核心动态关系:k 控制倾斜,b 控制上下平移,两者互不干扰。
```

被拦下的也要留一行记录,写清拦截理由,避免下次重复评估。

## 二、PRD — 生成前必须写完的六件事

PRD 不另开文件,直接作为 HTML 头部注释内嵌留档(见 CODE 规范第 1 条)。六个字段一个都不能空。

1. **一句话定位**
   这个动画让学生在 60 秒内亲手得到的那一个结论。不写功能列表,写结论。
   例:「k 决定直线倾斜的方向和陡缓,b 决定直线穿过 y 轴的位置,改一个不影响另一个。」

2. **核心误区**
   只写一条,写最常见的那条,后面的反馈文案要正面打它。
   例:「学生常把 b 当成『直线和 x 轴的交点』,或者认为 k 变了截距也会变。」

3. **单一认知动作**
   从下面七个里选**一个**,写进 meta 的 `cognitive`。选不出唯一动作,说明知识点该拆成两个动画。

   | 认知动作 | 含义 | 适合的知识点 |
   |---|---|---|
   | 比较 | 并排看两个对象的差别 | 两条直线的增减性、两组数据的离散程度 |
   | 分解 | 把整体拆成看得见的部分 | 面积拼图、多项式几何模型 |
   | 变换 | 对象在参数驱动下连续改变 | 函数参数、平移旋转对称 |
   | 逼近 | 一个过程越走越靠近某个目标 | 割线趋于切线、数列收敛 |
   | 守恒 | 表面在变,某个量一直不变 | 椭圆的定义、勾股关系、等价变形 |
   | 累积 | 结果由许多小单元叠加出来 | 面积累积、频数堆叠 |
   | 模拟 | 随机或迭代过程反复发生 | 频率趋于概率、迭代求解 |

4. **交互流程**
   写成「学生做什么 → 画面怎么响应 → 学生看到什么」的两三步,把手势方向写明。
   例:「向右拖 k 滑杆 → 直线绕 (0,b) 顺势变陡 → 右上方向的抬升幅度变大。」

5. **分步揭示设计**
   分 3 个阶段,写清每个阶段新增什么。阶段 1 只留最小可理解单元;公式一定在最后一个阶段。
   例:「阶段 1 只有坐标系和一条可调直线;阶段 2 加截距点和 Δx/Δy 直角标注;阶段 3 出解析式。」

6. **概念反馈文案**
   至少两条,每条 ≤ 2 句、第二人称、必须点出规律或不变量,禁止只报对错。
   例:「k = 1.8 是正数,所以 x 每往右 1 格,y 就抬 1.8 格 —— 这就是『k 为正时 y 随 x 增大』。」
   例:「注意 k 从 0.5 拖到 2.5 的整个过程,直线始终穿过 (0, b) 这一个点,b 一动没动。」

## 三、CODE — 强制规范

以下每条都是硬要求,`npm run validate:anim`(`apps/lab/tools/validate-animations.mjs`)会逐条检。
校验不过的文件不进人审。

### 1. 文件骨架与 meta

顺序固定:`<!DOCTYPE html>` → PRD 注释块 → `<html lang="zh-CN">` → head(meta / title / style)→ body → 内联 script。

必填 meta,六项齐全、名字大小写一致:

```html
<meta name="grade"    content="初中">                  <!-- 只能是 初中 | 高中 -->
<meta name="topic"    content="一次函数">              <!-- 教材口径的知识点名 -->
<meta name="difficulty" content="中">                  <!-- 只能是 低 | 中 | 高 -->
<meta name="cognitive"  content="变换">                <!-- 七个认知动作之一 -->
<meta name="desc"     content="拖动 k 与 b,看直线怎么转、怎么平移。">   <!-- ≤ 40 字 -->
<meta name="kpNodeId" content="MATH-JH-8B-19-CP13">    <!-- 知识图谱节点 id;没挂上就留空串 -->
```

`kpNodeId` 取 `data/knowledge-graphs/*.json` 里节点的 `code` 字段。查不到就 `content=""`,
不许编;manifest 会把空值显出来,人审时集中补挂。
另外必须有 `<meta name="viewport" content="width=device-width,initial-scale=1">`。

### 2. 教学法硬规则

- **一个动画只承载一个认知动作。** 顺手加的第二个功能(顺便讲讲解方程、顺便练两道题)一律砍掉,
  真需要就另开一个文件。
- **初始只给最小可理解单元。** 首屏只有阶段 1 的内容:核心图形 + 必要控件。标注、辅助线、
  公式默认不画,由「下一步」按钮逐层放出。
- **必有重置按钮。** 文案含「重置」或「重新开始」,一键回到阶段 1 与初始参数,学生随时能重来。
- **操作先于公式。** 解析式、定理式只允许出现在最后一个揭示阶段。禁止首屏顶部挂大公式再让学生「验证」。
- **交互方向与数学方向一致。** 滑杆右移对应参数增大,拖拽方向对应几何方向,曲线抬升对应函数值增大。
  确实存在方向反号的情况(如相位 φ 增大而图像左移),不许偷偷反过来接线:滑杆仍按参数增大接,
  同时在画面上画出真实平移方向,并在反馈文案里明说这个反号。
- **反馈揭示规律,不报对错。** 反馈区常驻在页面里(不用弹窗、不自动消失),写当前数值 + 它说明的规律
  或不变量。只出 ✓ / ✗ 视为不合格。
- **最多 3 种强调色。** 一种颜色只承担一个语义(一个参数、一个对象、一个不变量)。

### 3. 视觉与色板

暖色纸感基调,克制;所有颜色写成 `:root` 里的 CSS 变量,变量之外的地方不许出现裸色值
(十六进制、`rgb()`、`hsl()` 都不行),Canvas 绘图颜色一律用 `getComputedStyle` 读变量。
基础色板照抄下面这份(本项目自有色板,可按知识点微调强调色的色相,但保持暖底与 3 色上限):

```css
:root{
  --paper:#fdf8f0;        /* 页面底 */
  --sheet:#ffffff;        /* 卡片面 */
  --sheet-sub:#f5eee3;    /* 次级面 */
  --rule:#e8dcc9;         /* 分隔线 */
  --ink-1:#2a2118;        /* 正文 */
  --ink-2:#6b5d4c;        /* 次要文字 */
  --ink-3:#a49684;        /* 辅助文字、网格 */
  --hi-a:#b3541e;         /* 强调色 1 */
  --hi-a-soft:#fbe6d3;
  --hi-b:#256b60;         /* 强调色 2 */
  --hi-b-soft:#d9ece6;
  --hi-c:#6d4b9c;         /* 强调色 3 */
  --hi-c-soft:#e9e0f5;
  --tap:44px;             /* 触控目标下限 */
  --r-lg:12px; --r-sm:7px;
  --shade:0 1px 6px rgba(60,40,20,.09);
}
```

强调色变量只允许 `--hi-a` / `--hi-b` / `--hi-c` 三组(含 `-soft` 后缀),出现第四组即违规。

字体只用系统字体栈,**不许外链字体**:

```css
font-family:-apple-system,BlinkMacSystemFont,"PingFang SC","Hiragino Sans GB",
            "Microsoft YaHei","Noto Sans CJK SC",sans-serif;
```

数字与公式用等宽栈:`ui-monospace,SFMono-Regular,Menlo,Consolas,monospace`。

### 4. 尺寸与触控

- **375px 宽度不出横向滚动。** 单列布局,`body` 给 `overflow-x:hidden`,Canvas 宽度按容器实测宽度算,
  配合 `devicePixelRatio` 提清晰度。平板横放变宽时允许放大,不做第二套布局。
- **触控目标 ≥ 44px。** 按钮 `min-height:var(--tap)`;滑杆滑块和可拖点的命中半径按 22px 以上算,
  可拖点视觉半径可以小,命中判定要放大。
- 拖拽统一用 Pointer Events(`pointerdown`/`pointermove`/`pointerup`),可拖区域加
  `touch-action:none`,避免手指拖图变成页面滚动。

### 5. 安全规范

动画将来会被放进 `<iframe sandbox="allow-scripts">` 里跑,以下一律禁止:

- 外链资源:`<script src>`、`<link>`(含字体)、`@import`、`<img src="http…">`、iframe 嵌外站。
  图形自己画,图标用文字或内联 SVG。
- 网络请求:`fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`navigator.sendBeacon`。
- 跨窗口访问:`window.top`、`window.parent`、`window.opener`、`postMessage`、`window.open`。
- 本地存储:`localStorage`、`sessionStorage`、`indexedDB`、`document.cookie`。
- 动态求值:`eval`、`new Function`(校验器自己会用 `new Function` 做语法检,动画里不许用)。

动画是纯离线的一次性交互件,不留痕、不联网、不与宿主页面通信。

### 6. 自检清单(交付前逐条对)

| # | 检查项 |
|---|---|
| 1 | 六项 meta 齐全,`desc` ≤ 40 字,`kpNodeId` 真实或空串 |
| 2 | PRD 六字段以头部注释内嵌 |
| 3 | 只有一个认知动作,没有夹带第二个教学目标 |
| 4 | 首屏只有阶段 1;公式在最后阶段才出现 |
| 5 | 重置按钮存在且回到阶段 1 与初始参数 |
| 6 | 交互方向与数学方向一致,反号情形已在反馈里说明 |
| 7 | 反馈常驻、含数值、点出规律或不变量 |
| 8 | 强调色 ≤ 3 组,颜色全部走 CSS 变量 |
| 9 | 375px 无横向滚动,按钮 ≥ 44px,拖拽命中放大 |
| 10 | 无外链 / 无网络 / 无跨窗口 / 无存储 / 无动态求值 |
| 11 | 文件 ≤ 120KB,`npm run validate:anim` 全绿 |

## 四、管线位置

```
skill(本文件) → 生成 HTML → npm run validate:anim(确定性校验 + 生成 manifest.json)
              → 实验区「知识点动画」车间页逐个试玩 → 人审 → (未来)上资源库
```

校验器只管机械规范,教学法与数学正确性靠人审。人审重点看三样:
数学有没有错、首屏是不是真的只剩最小单元、反馈文案有没有真的说出不变量。
